# Vue 前端接管说明

本项目旧的 Jinja 模板前端已经删除，整站前端统一切到 `frontend-admin/` 这套 `Vue 3 + Vite + Element Plus` 架构。

## 当前状态

- `/admin` 后台入口：由 Vue 前端接管
- `/query` 前台提取入口：由同一套 Vue 前端接管
- Flask：仅保留后端业务逻辑、下载接口、任务处理和 JSON API

## 目录

- `frontend-admin/`：统一前端工程
- `pyfaka_app/routes.py`：后端路由与 JSON API
- `pyfaka_app/static/app/`：Vue 构建产物发布目录

## 已删除内容

- `pyfaka_app/templates/admin/`
- `pyfaka_app/templates/query/`
- `pyfaka_app/templates/layout.html`
- `pyfaka_app/static/app.css`

## 启动方式

### 本地开发

1. 启动 Flask 后端

```powershell
python run.py
```

默认：`http://127.0.0.1:8090`

2. 启动 Vue 前端开发服务

```powershell
cd frontend-admin
npm install
npm run dev
```

默认：`http://127.0.0.1:5173`

Vite 已代理 `/api/*` 到 Flask 后端。

### Flask 静态发布

如果需要让 Flask 直接提供前端页面：

```powershell
cd frontend-admin
npm run build
```

然后将构建产物同步到：

```text
pyfaka_app/static/app/
```

当前仓库里已经同步了一份可用构建产物。

## 路由说明

- Vue 前端页面入口由 Flask 直接返回 `pyfaka_app/static/app/index.html`
- `/admin`、`/admin/dashboard`、`/admin/login`、`/admin/files`、`/admin/files/<id>`、`/admin/cdkeys`、`/admin/cdkeys/<id>`、`/admin/tasks`、`/admin/audit`、`/admin/users`、`/admin/settings`
- `/query`：当前唯一的前台提取工作台入口
- `/query/progress/<job_id>`：兼容旧链接，进入后会立即跳转到 `/query?job_id=...`
- `/query/result`：兼容旧链接，进入后会回到 `/query` 单页工作台

## 说明

- 旧模板前端已不再保留兜底页。
- 文件下载、卡密下载、结果下载等仍由 Flask 原有后端接口提供。
- 当前仍保留部分旧后端路由用于兼容下载和任务处理，但页面渲染层已全部下线。
- 新后台当前已补齐文件详情、卡密详情和审计日志页，详情页只展示运营排查所需摘要，不直接向前端暴露敏感 token 原文。
- 后台作用域已统一收口到右上角；当前不再提供顶部用户切换，归属用户固定为当前登录账号，业务类型切换后文件池、卡密和总览都会按同一范围刷新。
- 右上角范围区已做去重和紧凑化处理，业务类型与标签保留在原位置，但交互更偏向后台筛选条，不再堆叠重复摘要信息。
- 右上角作用域切换当前由顶层布局统一接管，业务类型和标签切换会直接写回全局作用域状态，再触发各页面按同一范围重新请求数据。
- 系统设置页当前支持维护业务类型：业务编码作为卡密前缀，创建保存后不能修改；显示名称可单独维护，并用于后台切换项和 `/query` 库存封面展示；`启用` 决定后台是否可选，停用后前台也不会展示；`前台显示` 只在已启用时生效，决定 `/query` 库存封面是否展示；删除或停用当前业务类型后，右上角会自动切到仍启用的第一个业务类型。
- 管理员现在默认查看自己的数据范围，不再默认切到“全部用户”。
- 卡密页已改成极简结构：主界面只保留“卡密生成”和“超发”按钮；生成成功后会自动复制，并保留“复制最近生成”入口，不再弹出二次结果弹窗，避免列表刷新时页面抖动。
- 超发额度按用户和业务类型独立保存；切换业务后读取和修改的是当前业务额度，同一业务下各分组共同消耗该业务额度，旧的全局额度仅作为尚未单独配置业务的兼容初值。
- 卡密页当前支持文本导入未提取卡密；系统会按卡密前缀解析每张文件数和业务类型，自动生成 `IMPORT-YYYYMMDD-*` 批次，`group_tag` 固定写入 `default`；重复卡密会自动跳过并返回统计，格式错误仍会整批失败。
- 卡密页当前已补“导出筛选结果”入口，直接复用现有后台导出链路，按当前筛选条件导出最多 10000 条卡密 CSV。
- 卡密页当前额外支持“导出已选 TXT”，直接将当前勾选的卡密导出为纯文本文件，每行一张卡密。
- 上传、删除、测活任务已统一进入 `/admin/tasks` 页面展示后台进度明细；文件池发起这些任务后会直接跳到任务进度页，不再在文件池内嵌显示进度条。
- 任务进度页当前采用“顶部任务状态 + 下方结构化明细表”结构；测活任务明细展示邮箱名称、注册时间、测活时间、额度、额度周期、套餐类型和状态码，不再把阶段、RT 和事件文本混入表格。
- 任务进度页当前进一步按任务类型拆分字段：测活任务继续展示邮箱、注册时间、测活时间、额度和状态码；上传、删除任务改为只展示邮箱、成功/失败结果和明细，不再塞测活字段。
- 任务进度页顶部“异常”统计 pill 当前支持点击筛选，上传和删除任务可直接一键只看失败记录，便于运营快速排查失败原因。
- 任务进度页顶部“异常”统计 pill 当前已修正为按任务类型过滤：上传/删除筛失败结果，测活/提取筛非 200 状态记录，避免异常数存在但点击后空表的情况。
- 任务进度页当前已补本地分页，支持页码切换和每页条数下拉；顶部任务状态也改成长进度条样式，统一按“已处理 / 剩余 / 百分比”展示。
- 任务进度页与前台提取页的顶部进度区目前都已压缩成紧凑版状态条，主要信息保留，但明显减少了头部占用高度。
- 任务进度页当前进一步收口为“细进度条 + 分类统计 pills”结构，可直接看到正常、异常、跳过、覆盖等分类数量，不再使用大块右侧数字区。
- 任务进度页下方明细表当前已改为更偏自适应的宽列布局，优先把右侧空白回收到列表本身，而不是额外堆叠装饰区。
- 任务详情轮询接口当前也统一走任务摘要转换，顶部正常/异常等分类数量会随轮询自动刷新；上传任务进行中也会实时补出注册时间、测活时间、额度和状态码，不必等到任务完成后才看到。
- 上传任务当前额外提供可见批次号，采用 `UP-YYYYMMDD-ID` 格式直接展示在任务顶部和上传明细中，用于运营追踪同一批文件；这轮仅做界面追踪号，不涉及数据库字段变更。
- 前台提取任务当前额外提供可见提取编号，采用 `EX-YYYYMMDD-任务前缀` 格式展示在后台任务列表和任务详情顶部；同一次多卡密提取共用一个编号，并会写入已提取卡密和绑定文件，文件池与卡密列表都支持按该编号查询筛选。
- 前台游客流程统一收口到 `/query` 单页工作台，并拆成“卡密提取”“重登授权”和“邮件查看”三个标签页；各自的输入、设置、进度、结果和下载在对应标签内完成，不再混排，也不依赖 `progress -> result` 两页跳转。邮件查看默认关闭，超级管理员可在系统设置中开启。
- 旧的 `/query/progress/:job_id` 和 `/query/result` 仅保留兼容入口，都会立即回到 `/query` 并携带当前 `job_id`。
- 前台提取页右侧进度头当前统一只按“已提取结果数 / 目标数”显示，并固定使用“提取进度”标题；任务失败或被中断时只展示失败状态，不再继续请求完成结果接口。
- 前台提取主进度区当前去掉重复数字，只保留左侧长进度条、右侧 `已提取 / 目标数` 和百分比；下方结果表支持分页和每页条数下拉。
- 前台提取页的两个下载动作已切到前端接管，可在页面内看到下载进度条，不再是无反馈的直接跳转下载。
- 前台提取页的下载反馈已改成按钮区内的轻量状态胶囊，不再额外插入一条下载进度卡片，避免打乱提取结果区布局。
- 前台提取页的“已提取”口径已统一为结果文件数，不再错误使用“已测过多少候选文件”的统计值。
- 前台提取页当前通过监听 `job_id` 路由参数统一接管轮询状态；无论是新提交、刷新页面还是从旧兼容链接进入，都会在同一页持续更新，任务未完成前不会显示任何下载按钮。
- 前台提取页当前会先读取任务状态再决定是否拉取最终结果，任务进行中不会再误报“任务尚未完成”；任务完成后结果会自动落到当前页，无需手动刷新。
- 前台提取结果列表与文件测活任务明细当前统一按额度倒序展示，额度高的账号优先排在上面，并同时显示额度周期和套餐类型；未测活或无额度信息的记录会自动排到后面。
- 前台提取页完成态会再拉一次最终结果接口，因此额度倒序必须同时在轮询态和最终结果接口生效；当前两条链路都已补齐，避免完成后顺序被覆盖打乱。
- 前台工作台顶部保留自动轮询的紧凑库存条；主区域固定为三个流程标签，桌面端限制为稳定工作宽度，移动端标签、操作栏和下载组改为单列或受控双列，宽表仅在表格容器内横向滚动。
- 后台右上角作用域当前不再向用户暴露“标签/default”切换；界面只保留用户范围与系统设置中启用的业务类型，标签继续作为内部默认值透传，避免无意义筛选干扰操作。
- 右上角切换业务类型后，今日总览和任务进度都会按当前业务类型隔离；新任务会写入业务类型，旧历史任务如果没有业务类型只在默认 `free` 视图里兜底展示。
- 文件池页已去掉页内任务提示，任务开始后直接跳转到任务进度页查看后台执行明细。
- 文件池列表当前在“测活”和“额度”之间展示“测活代码”列，直接显示最近一次测活返回的 HTTP 状态码，未测活显示 `-`。
- 系统设置支持多选“不可出库状态码”，默认选择 `401`；提取测活和后台文件测活命中任一选中状态码都会标记不可出库，其他未选中的非 200 状态仍会放回原库存状态。
- 文件池页当前新增“下载已选”和“下载筛选结果”后台任务入口；下载会先进入任务进度页打包，完成后在任务详情里提供下载包按钮，并记录每个文件的下载时间。
- 新上传账号的 auth 内容当前按字段拆分保存到数据库 `file_record_payload_py`，不再写入 `data/auth_files/*.json`；`client_id`、`device_id`、`password`、`user_agent` 不保存也不导出。上传批次按原子口径处理，任一文件失败则整批账号不入库；数据库写入失败时任务与审计只记录脱敏错误信息，不记录账号字段值。
- 任务进度页当前改为左侧历史任务列表、右侧任务详情结构；历史任务会持久化到 `data/task_history.json`，最多保留 200 条后台任务快照，服务重启后仍可查看历史状态和结构化明细。
- 任务进度页左侧历史任务当前按天分区展示，优先使用上传、下载、删除等业务操作时间，缺失时用任务更新时间兜底，方便按日期回看当天任务。
- 任务进度页当前支持按日期、任务类型和任务状态筛选历史任务；筛选后右侧详情会自动切到筛选结果内的任务，避免列表和详情展示不同范围的数据。
- 任务进度页当前对前台提取、游客重登授权、上传、下载、删除和后台文件测活任务都提供“终止任务”：超级管理员可查看和终止游客重登授权，普通后台用户不可见；历史中残留但当前进程已不再执行的任务会直接标记为中断，当前进程里仍在执行的任务会进入“正在终止任务”并在当前批次处理点协作停止。前台提取和后台文件测活会继续释放该任务自己记录过的 `CHECKING` 锁，上传、下载、删除则在安全提交点前回滚并结束；重登授权默认并发 `10`、最大并发 `10`，同一张卡密或重叠多卡请求只允许一个排队或运行中的任务，重复提交会回到已有任务。
- 游客重登授权页面和超级管理员任务详情统一使用账户进度表，将测活结果、授权状态和当前日志合并到每个账号自己的行；HTTP `401`、需要授权的账号置顶，正常账号仍保留并显示“无需授权”。表格默认每页 `10` 条，支持 `10/20/50/100` 条切换，当前任务不会在 200 条账户处截断。
- 每个账户行可展开最近 `30` 条过程日志，覆盖测活、密码与 2FA 验证、令牌回写和授权结果。2FA 验证失败时提示检查密钥和服务器时间；验证码验证阶段的 HTTP `403` 仍保留封禁逻辑，`rate_limit_exceeded` 保留 5 分钟冷却。任务结果提供 CPA ZIP、sub2api JSON 和 2FA TXT，成功账号与原卡密全部账号分开下载。
- 游客“2FA 验证码”通过卡密加载绑定账号，本地生成六位 TOTP，到期自动清空。前后端共同执行 `5` 秒刷新冷却，结果区分三行展示“邮箱”“密码”“2FA 动态码”，每行附用途说明；动态码行突出显示，到期提示刷新。验证码接口仅返回当前卡密绑定账号的登录密码，不返回 2FA 密钥，响应不缓存；切换邮箱或卡密时清除旧账号密码和动态码。后台文件池新增“导入 2FA 库”，支持 TXT 或粘贴三段式文本，按当前文件池邮箱自动匹配；游客提取结果新增“2FA TXT”下载。
- 任务历史写入属于辅助记录；如果 Windows 临时锁住 `data/task_history.json`，系统会短暂重试并跳过本次快照，不会中断上传、下载、删除或测活主任务。
- 服务启动时会检查历史中仍处于排队或运行中的前台提取、文件测活任务；已实际完成出库的提取任务会补标完成，未完成的中断任务会标记为“任务已中断”，并优先按任务快照里记录的卡密和文件锁释放残留状态，需要用户重新发起。
- 文件池“恢复提取测活中的文件”当前会自动跳过仍被活动前台提取或后台测活任务占用的 `CHECKING` 文件，避免把正在运行的任务锁误恢复掉。
- 前台提取、上传、下载、删除和后台文件测活任务当前都带固定 30 分钟任务级超时；超过后会自动标记为“任务执行超时”。前台提取和后台文件测活会释放该任务自己仍持有的锁，上传、下载、删除会在下一次安全检查点停止并回滚未提交数据，下载中的半成品 ZIP 也会删除。
- 上传任务进行中仍会实时更新内存进度，但历史快照文件会按时间间隔节流写入；任务完成或失败时仍会立即保存最终状态，避免大批量上传时每个文件都触发一次 `task_history.json` 写盘。
- 删除任务进行中同样会节流历史快照写入；大批量删除会按固定大小分块执行查询和删除 SQL，并在任务末尾统一提交账号、payload 和审计记录。
- 下载和测活任务进行中同样会节流历史快照写入；大批量下载和后台文件测活会按固定大小分块读取文件 ID，避免单条 SQL 参数过多。
- 提取候选账号和提取结果下载当前增加复合索引，并把账号 payload 改为优先复用已预加载数据、缺失时按文件 ID 批量读取，减少大库存下候选账号查询、绑定文件查询、测活候选和下载/结果页 payload 读取耗时。
- 上传、下载、删除任务明细当前统一展示对应操作时间：上传任务显示上传时间，下载任务显示下载时间，删除任务显示删除时间；提取过程中的结果列表会在出库候选阶段显示注册时间和提取时间，完成后再用数据库正式出库时间覆盖。
- 文件池页的“上传文件目录”按钮已并入搜索筛选同一行，并固定贴右显示，避免单独占一行头部空间。
- 文件池和卡密列表当前都同时支持两类批量动作：`已选项操作` 和 `当前筛选结果操作`，避免用户每次都必须手工全选当前页。
- 前台 `/api/query/access` 允许公共页直接发起提取请求，不再被后台登录态 CSRF 校验误拦截；如果提取失败，优先看接口返回的库存不足等业务提示。
- 后台登录当前已增强防爆破：账号加 IP 连续失败 10 次会锁定，单 IP 总失败 10 次也会锁定；登录失败统一延迟并隐藏用户是否存在。新建、重置和首次修改密码统一要求至少 10 位且包含字母和数字。
- Flask 当前会默认发送基础安全响应头，并设置后台会话 Cookie 为 `HttpOnly`、`SameSite=Lax`；HTTPS 场景可通过 `PYFAKA_COOKIE_SECURE=1` 启用 Secure Cookie。
- 前台卡密提取当前增加访问令牌校验：提交卡密后返回的 `job_id` 必须和本次 `access_token` 同时匹配，才能轮询进度、查看结果和下载文件；访问令牌同时绑定本次提交的卡密范围，即使复用同一个运行中任务，也只展示和下载本次输入卡密对应的结果；连续 10 次提交无效卡密会锁定 30 分钟，降低卡密爆破和结果越权风险。
- 系统设置页已移除“自动清理时间”，后台不再启动定时自动清理任务，避免系统在固定时间自动清理提取相关数据。
- 文件池和卡密页的“删除筛选结果”已改为危险操作二次确认：先预览当前筛选会删除的文件数、卡密数和绑定文件数，再要求输入“确认删除”后才会执行。
- 今日总览已补充当前范围下的可用文件数；登录页支持选择记住用户名或记住密码，记住密码仅保存在当前浏览器本地，适合自用设备。
- 文件池、任务进度和前台提取结果中的额度显示已统一为纯百分比，例如 `95%`，不再展示“剩余额度”等中文前缀。
- 前台提取下载接口在带 `job_id` 的前端下载场景下会返回 JSON 错误，不再把失败重定向页当作下载文件返回；提取页也会同时监听 `job_id` 和访问 token 变化。

## sub2api 批量账号上传

文件池提供“上传 JSON / sub2api”按钮，可以直接选择单个或多个 JSON 文件；原“上传文件目录”继续支持目录上传。后台自动识别普通 auth JSON 和包含 `accounts` 列表的 sub2api JSON，并将批量文件拆成独立账号入库，任务数量按账号数显示。例如含 13 个账号的单个 JSON 会产生 13 条上传结果。

sub2api 仅接收 `platform=openai`、`type=oauth` 的账号。邮箱依次取 `credentials.email`、`extra.email`、邮箱形式的 `name`；令牌从 `credentials` 读取，账户 ID 优先取 `chatgpt_account_id`，刷新时间取 `credentials.last_refresh` 或 `extra.last_refresh`，到期时间支持原 `expired` 或 Unix 秒数 `expires_at`。代理、并发、优先级等 sub2api 配置不导入本系统。

普通 JSON 与 sub2api JSON 可以混合上传。同批重复邮箱、缺少必要凭据、其他平台账号、无效格式或已绑定账号覆盖均会使整批取消。未绑定同邮箱账号沿用覆盖规则，已导入的 2FA 凭据保持不变；匹配范围仍限定当前用户、业务类型和标签。
