# 前台提取说明

前台提取页默认勾选“提取前测活”。勾选后，系统会先测活，只有 HTTP 200 的账号进入出库结果。

测活任务明细和卡密提取结果会同时展示剩余额度、该额度对应的周期以及账号套餐类型。额度周期取当前使用率最高的限制窗口，例如 `5小时` 或 `7天`；套餐类型取测活接口返回的 `plan_type`。未测活或旧任务未采集到的数据分别显示“未测活”或“暂无”。

用户取消勾选时，系统会直接按库存出库，不做测活校验；该方式的提取结果不提供测活质保。

测活失败时系统会自动重试一次。系统设置中的“不可出库状态码”支持多选，命中任一选中状态码都会被视为明确失效并标记为不可出库，默认选择 HTTP 401；其他状态或网络异常会放回库存，不在前台显示为死号。命中不可出库状态码时不再重复测活。

提取过程中，页面只显示出库列表。顶部进度固定按“已提取结果数 / 目标数”显示，账号进入出库结果时会逐条追加到列表里；当列表数量已经达到目标但任务还在提交最终结果时，页面会显示“正在整理结果”，避免把收尾阶段误判成卡住。下载 ZIP 时页面会显示下载进度。

再次输入已经提取过的卡密，或输入仍在提取中的卡密时，系统会进入对应出库进度页并显示当前进度或历史提取结果。重复提取已完成卡密时，系统会从该卡密最近一次完成的提取任务恢复额度周期和套餐类型，不会因为从数据库重建结果而显示为“暂无”；未勾选测活的任务仍统一显示“未测活”。若复用的是一个包含多张卡密的运行中任务，前台只会展示和下载本次输入卡密对应的结果，不会扩大到同一任务里的其他卡密。

如果服务在提取或测活任务运行中重启，启动恢复会把未完成任务标记为“任务已中断”，释放残留锁定状态；用户需要重新提交卡密继续提取。若数据库中卡密和文件已经完成绑定，系统会补标该任务为完成。

系统每天会在设置页配置的时间统一删除首次提取时间超过 1 天的卡密和相关文件，默认时间为 `12:00`，保存后无需重启即可生效，用户应在出库完成后及时下载。

默认 ZIP 下载内容是账号 auth JSON 压缩包。

账号 JSON 上传不再要求 `mailinfo`。后台文件池新增“导入 2FA 库”，支持粘贴多行文本或选择 UTF-8 TXT 文件，每行格式为：

```text
user@example.com--账号密码--Base32的2FA密钥
```

导入按邮箱忽略大小写，自动匹配当前用户、业务类型和标签文件池中的已有账号，已绑定卡密的账号也可补充或更新。导入只更新账号密码与 2FA 密钥，不改变令牌、库存状态和卡密绑定。邮箱重复、格式错误、密钥无效或邮箱未匹配时，整批不写入并返回原因；不会创建空账号。重复导入会更新对应账号的凭据，已有封禁或限流状态保留。

游客完成卡密提取后可以选择“2FA TXT”下载，每行仍为 `邮箱--密码--2FA密钥`。下载仅包含本次卡密授权范围内的账号；缺少 2FA 信息时返回明确错误，不输出缺项文件。CPA 下载的账号 JSON `type` 固定为 `codex`，CPA 和 sub2api 下载仍只包含令牌字段；验证码查询返回当前卡密绑定账号的邮箱、登录密码和动态码，供页面分三行展示；不返回 2FA 密钥。账号列表和任务日志不返回密码或密钥。

游客界面在同一个工作台中使用“卡密提取”“重登授权”和“2FA 验证码”三个标签页；验证码功能默认开启，超级管理员可以在系统设置中关闭。每个标签页独立展示自己的输入、设置、任务进度、结果与下载操作；任务存在时，宽屏页面采用左侧提交、右侧进度与结果的双栏布局，窄屏自动恢复上下布局。页面重新载入已有任务链接时，会自动切换到对应流程。重登授权标签页输入一个或多个卡密后执行，卡密按行分隔，默认并发为 `10`，最大为 `10`。系统会先在后台对卡密绑定的全部文件重新测活，测活完成后只筛选最新 HTTP 状态为 `401` 的账号，再使用导入的账号密码登录，并在 MFA 挑战中提交本地生成的 TOTP 验证码完成重新授权；如果本次测活没有得到 `401` 账号，任务会结束并提示没有可重新授权的账号，不会直接执行授权。单个账号成功后会用新令牌覆盖原账号记录，失败账号保持原数据不变。同一张卡密只能同时属于一个排队或运行中的重登授权任务；重复提交单卡或多卡请求，只要与已有任务有任一卡密重叠，就返回已有任务的访问凭证并回到该任务界面，不会启动新任务。重登详情使用一张账户进度表融合测活、授权状态和过程日志；“本次重登授权成功文件”只包含本次成功账号，并同时提供 CPA ZIP、sub2api JSON 和 2FA TXT 下载。“原卡密最新文件”也提供这三种格式，包含卡密全部绑定文件，其中成功账号使用回写后的令牌。

验证码提交返回 HTTP `403` 时，不再区分上游错误码，任务结果和关键日志统一显示“账户封禁”，并写入永久封禁标记，后续重登授权直接跳过。其他非验证码验证阶段的普通 HTTP `403` 不会被自动归类为账户封禁。OAuth 任一上游流程返回结构化错误码 `rate_limit_exceeded` 时，直接显示“账户已被限流，5分钟后再重试”；系统记录限流时间，5 分钟冷却期内跳过该账号，冷却期结束后自动允许再次 OAuth。这两类账号状态都会持久化到该账号的服务端授权信息，再次上传同一账号时保留标记；封禁标记永久有效，限流标记只在冷却期内有效。普通网络 `429` 不会被自动归类为限流状态。游客授权结果和超级管理员任务明细都展示成功、失败账号及具体原因，下载内容仍只包含本次 OAuth 成功账号。

OAuth 调度按账号邮箱分组，同一账号串行，不同账号共享设置的并发数，默认 `10`、最大 `10`。流程不再登录 Mail 邮箱或轮询邮件；若上游仍要求邮箱验证，本次授权明确失败，不将 TOTP 提交到邮箱验证码接口。2FA 密钥必须对应目标账号，服务器时钟需要准确。

重登授权任务会在同一张账户进度表中实时展示登录前测活和逐账号授权过程，包括邮箱、正常/异常/跳过状态、HTTP 状态码、授权状态、当前日志、剩余额度、额度周期和套餐类型。最新测活为 `401`、需要授权的账号固定排在顶部，其余正常账号仍各占一行并显示“无需授权”。表格默认每页 `10` 条，可切换 `10/20/50/100` 条；切换任务或清除结果时回到第一页。当前运行任务保留全部账户行，不会在 200 条处截断；测活明细在进入授权后及任务结束后仍会保留。

游客重登授权和管理员任务详情按账户保留最近 `30` 条过程记录，覆盖测活、账号密码与 2FA 验证、令牌刷新和回写结果。密码、2FA 密钥和令牌不写入公开日志。

任务排队或运行时，游客可在重登授权页点击“停止任务”。系统会在当前测活检查点或当前正在执行的最多 `10` 个授权账号完成后停止，不再启动下一批账号；已经成功回写的账号不会回滚。超级管理员可在后台任务中心筛选“重登授权”，查看游客任务、测活明细和并发数，并提交同样的协作式终止；普通后台用户看不到游客任务。服务重启时，历史中未完成的重登授权任务会标记为中断，不会继续占用卡密。

游客在“2FA 验证码”中输入卡密后，只能加载该卡密绑定且已导入 2FA 的账号。选择邮箱并点击获取后，服务端本地生成六位 TOTP 验证码，每 `30` 秒变化。接口返回剩余有效秒数，页面到期自动清空验证码。刷新仍有 `5` 秒冷却，返回 `TOTP_REFRESH_COOLDOWN` 和 `retry_after=5`。

接口：`POST /api/admin/files/import-2fa` 接收 `text` 及当前池范围；`POST /api/query/2fa/accounts` 接收 `code`；`POST /api/query/2fa/code` 接收 `code`、`email`。游客下载 `GET /query/files/download-2fa` 沿用提取任务的 `job_id`、`token`；重登结果下载新增 `format=2fa` 和 `format=card-2fa`。原 `/api/query/mailboxes`、`/api/query/mail/latest` 已移除。

服务端继续复用已有物理 `mailinfo` 列保存授权信息，程序属性改为 `reauth_info`，无需修改数据库结构。旧 Mail 数据不再用于登录，成功导入后对应行替换为账号密码、`totp_secret` 和保留的账号状态。上线需重启后端并发布本次构建的静态页面；已有部署 ZIP 未在本任务中更新。

sub2api 下载会把已提取账号转换为 sub2api 导入 JSON，账号名优先使用邮箱，平台为 `openai`，账号类型为 `oauth`，默认并发为 `3`，优先级为 `50`。

卡密服务台顶部常驻提醒：“卡密信息将在提取 24 小时后删除，请及时下载并妥善保存 2FA 文件。”普通提取、本次重登授权成功文件及原卡密最新文件中的 2FA 下载入口统一显示为深橙色加粗大按钮“下载 2FA 文件”，仍由用户单独点击下载 TXT。

“2FA 验证码”标签增加“邮箱 / 密码 / 验证码”副标题；栏内提示输入卡密、加载邮箱并选择账号后，点击“获取验证码”查看登录邮箱、账号密码和当前 2FA 验证码。
